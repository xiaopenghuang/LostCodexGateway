# 故障排除

## 连接类

| 症状 | 错误提示（应用内） | 原因与处理 |
|---|---|---|
| 点连接立刻报错 | 服务器域名解析失败 | DNS 问题；检查主机名拼写或改用 IP |
| 连接十几秒后失败 | 服务器不可达 | 服务器 IP/端口不对、防火墙、服务器关机；`测试连接` 确认 |
| 连接失败 | 鉴权失败 | 私钥不对/无权限；检查私钥路径与服务器 authorized_keys |
| 连接失败 | Host Key 已变化（已阻断） | 服务器重装/中间人风险；核对后到「服务器」页重新确认指纹（写前自动备份旧 known_hosts） |
| 连接失败 | 本地端口被占用 | 换 SOCKS 端口（设置里改） |
| 隧道建立但验证失败 | 远端禁止 TCP 转发 | 服务器 `sshd_config` 的 `AllowTcpForwarding` 被禁用；本工具**不会**替你改服务器配置 |
| 连接卡 30 秒 | 直连对照失败（如实显示） | 本机直连被网络策略拦截（实测环境如此）；不影响隧道出口验证结论 |
| 出口 IP 与「对照」相同 | 页面黄色提示 | 出口路径可能重叠；用诊断页确认（实测环境对照走用户现有代理，隧道走服务器，两者不同） |

## 客户端类

| 症状 | 说明 |
|---|---|
| Codex CLI 提示网络错误但隧道正常 | 确认 CLI 是从「应用」页启动的（代理只注入本工具启动的终端）；确认状态是「出口已验证」 |
| 想验证 CLI 是否真走隧道 | 「应用」页桥接统计（连接数/最近目标）即证据；也可看服务器 sshd 日志的转发会话 |
| OAuth 登录打不开 | localhost 回调必须直连——NO_PROXY 已注入，不要手动删 |
| Desktop/IDE 没走隧道 | 应用如实显示「TUN 未开启/尚未覆盖」；见 setup-windows.md 第 4 节 |
| WSL2 里的 Codex | v1 不支持，不假装生效 |

## Mihomo 规则类

| 症状 | 处理 |
|---|---|
| 订阅更新后规则片段消失 | 你的 profile 链覆盖了片段文件；重新按 setup-windows.md 导入，或把片段放进你的 merge profile |
| 回滚按钮报「目标文件在备份后被修改过」 | 这是安全设计：检测到用户改动，拒绝覆盖。人工比对备份与当前文件后处理 |
| 检测显示 secret | 正常：应用只报告「有 secret」，不读取、不保存该值 |
| Verge 未运行 | 检测如实报告；规则片段生成不依赖运行状态 |

## 诊断导出

「诊断」页 →「导出脱敏诊断报告」→ 生成 `%APPDATA%\LostCodexGateway\diagnostics_时间戳.txt`。
内容：状态、服务器地址、端口、验证步骤与时间戳、日志（仅域名/状态/错误类别）。**不含**私钥内容、Token、请求正文、项目内容。

## 已知限制（v1 如实声明）

1. IPv6 / UDP 不承诺经 SSH SOCKS 转发（OpenSSH -D 语义所限）。
2. 不保证 WSL2、Docker 容器内 Codex 的 Windows 进程级规则覆盖。
3. 断线策略为「停止新启动并警告」，不给第三方应用提供全局 kill-switch。
4. Windows 9.5 的 ssh-keyscan 不支持 `-o`（无法显式限定 KEX）；若服务器只声明 `sntrup761` KEX，指纹获取会失败并明确提示（可临时用 Git 自带新版 ssh 或升级 Windows OpenSSH）。
