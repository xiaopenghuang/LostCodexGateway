## 二、已知限制与未实现项（如实声明，不在 UI 假装生效）

| # | 项 | 状态与影响 |
|---|---|---|
| R1 | **IPv6 / UDP 不经 SSH SOCKS 转发** | OpenSSH `-D` 语义所限；v1 不承诺。诊断页可检测但默认不展示"已支持" |
| R2 | **WSL2 内 Codex：已提供只读探测，NAT 模式下不可用** | 已新增 WSL2 专项模块（只读探测 + 一次性注入命令）。实测判据是「在 WSL 内真正建连成功」：mirrored 模式可直接用 `127.0.0.1`；**NAT 模式（默认）下 Windows 侧 SOCKS 只绑 127.0.0.1，WSL 连不上**，页面如实报不可达。本工具不代做需要提权的端口转发 |
| R3 | **Codex Desktop/IDE 的 TUN 分流未覆盖** | 实测用户环境 TUN 关闭（TAP 网卡 Disconnected）。应用如实显示「尚未覆盖」；开启 TUN 由 Verge 官方组件处理 |
| R4 | **规则片段不自动注入订阅** | 订阅更新后可能丢失规则片段（取决于用户 profile 链）。v1 只提供生成+备份+手动导入+回滚，不做订阅注入 |
| R5 | **桥接/SOCKS 端口无客户端鉴权** | 所有本地代理工具的共同属性：本机任意进程可连 127.0.0.1 端口使用隧道。v1 记录为已知限制（端口随机+仅回环已降低风险） |
| R6 | **Windows 9.5 ssh-keyscan 不支持 -o / sntrup761 KEX 处理有缺陷** | 服务器只声明 sntrup761 时指纹获取失败并明确提示；临时方案见 troubleshooting.md |
| R7 | **本机直连被网络策略阻断时的对照出口** | 对照出口显示「直连失败」是如实报告（实测环境如此）；不影响隧道验证结论 |
| R8 | **断线策略仅为「停止新启动并警告」** | 不给第三方应用全局 kill-switch（文档明确不做）；已启动的 codex 会话在隧道掉线时由监控任务置 DISCONNECTED |
| R9 | **IDE（VS Code）Codex 插件未实测** | 实测环境 `.vscode/extensions` 无 codex 插件目录；M3 交付进程发现框架，插件场景待用户安装后按同一流程验证 |
| R10 | **单实例守卫已实现，但未在多用户/远程桌面场景实测** | 命名互斥体 `Local\LostCodexGateway.SingleInstance` 已生效：第二个实例不会起隧道，只 `SetEvent` 唤出旧窗口后退出。用 `Local\`（会话级）而非 `Global\`，故同一机器上不同登录用户可各自运行一份。**注意**：`Local\` 在「快速用户切换」与 RDP 断线重连下的行为未实测 |
| R11 | **服务器侧 sshd 预检未自动化** | `AllowTcpForwarding` 禁用时在连接阶段报「远端禁止转发」；不做连接前自动探测（避免额外登录会话） |
| R12 | **未实现：配置导入/导出** | 多机同步服务器配置需手工复制 `%APPDATA%\LostCodexGateway\config.json`；v1 无内置导入导出 UI |
| R13 | **备份文件无自动清理** | `config.json.bak_*` 与 `<profile>.bak_lcfg_*` 只增不减，长期使用会积累。v1 不自动删除（避免误删用户数据），需人工清理 |
| R14 | **`restore_mihomo_file` 为整文件等价比对** | 仅当目标当前内容与备份**逐字节相同**或目标不存在时才回滚；备份后被追加过任何内容即拒绝（保守优先，绝不覆盖用户改动） |
| R15 | **开机启动写入的是当前 exe 路径，安装位置变更后失效** | 升级或移动安装目录后注册表条目仍指向旧路径；设置页会标记「指向其他程序」并拒绝自动删除，需用户手动重新启用 |
| R16 | **切换服务器是硬切，进行中的请求会断** | 单端口模型下无法做优雅切（两条隧道不能同时绑同一端口）。切换瞬间正在跑的 Codex 请求会失败，需重试。UI 在切换前会明确提示并二次确认 |
| R17 | **切换失败不自动回滚** | 设计选择：回滚会让用户看到「点了切换但没变」。改为如实报错 + 保留 `previous_server_id`，界面出现「切回上一个」按钮。**若用户忽略报错直接关闭应用，配置里选中的仍是那台连不上的服务器** |
| R18 | **延迟探测不是出口延迟** | `test_servers` 只做 TCP 握手探测（不建隧道、不认证、不发数据），测的是「到服务器 SSH 端口的往返」。出口速度/稳定性与它没有直接关系，UI 已如实标注，但用户仍可能误读 |
| R19 | **隧道运行期间不能改本地端口** | `save_settings` 在隧道活跃时拒绝改端口（否则正在跑的桥接层与配置指向不一致）。用户需先断开再改，改完重新连接才生效 |
| R20 | **多服务器未做真机端到端实测** | 切换逻辑有单元测试覆盖不变量（切服务器不改端口、改名不改 id、删当前项后选中项不悬空），但「A 断开 → B 连上 → 出口 IP 确实变成 B 的」这条完整链路尚未在真实双服务器环境验证，需用户提供第二台服务器后补测 |
| R21 | **桥接层目标黑名单基于字面量，域名解析在远端** | 黑名单能拦住 `127.0.0.1` / `192.168.x.x` 这类**字面量**目标，但形如 `internal.corp.example.com` 的域名由远端 DNS 解析，本地无从判断其真实 IP。这是「远端 DNS」语义的必然结果（也正是能正常访问外网的前提），不做本地预解析——预解析会破坏远端 DNS 能力并泄露查询 |
| R22 | **0.3.0 安装包已产出，但未做安装/卸载冒烟** | 产物路径与 SHA-256 见 `acceptance-report.md` §5.7。0.1.0 做过静默安装 / 卸载 / 启动冒烟（§4.2），0.3.0 未重跑：本次构建在沙箱内执行，`reg.exe` 被安全策略拉黑（无法核对注册表卸载项），且安装会写入工作区之外的 `%LOCALAPPDATA%`。需在真实桌面会话中补跑 |

## 二点五、网络诊断模块的已知限制

| # | 项 | 说明 |
|---|---|---|
| D1 | Mihomo 连接关联依赖 external-controller 只读可达 + secret | 用户不提供 secret 时如实显示「未获取到连接记录」，绝不猜测 |
| D2 | Desktop/IDE 路由验证依赖 TUN | 实测环境 TUN 关闭 → 如实显示「未验证」；开启 TUN 由 Verge 官方组件处理 |
| D3 | CLI「已验证」的判定为构造性论证 | 桥接层 100% 走隧道（构造保证）+ 桥接有连接记录 + 网关出口 OK；仍在页面注明「单条连接不能推断全部流量」 |
| D4 | 本地/网关出口可能相同 | 实测环境本地直连与服务器出口同为 203.0.113.47（网络拓扑所致）；页面会显示两值供用户自行比对，并在相同时不谎报差异 |
| D5 | 服务器检测依赖 wget/curl/nc 其一 | 缺失时 HTTPS/TCP 探测会如实显示失败原因（命令模板固定，不安装软件） |
| D6 | 进程枚举为快照 | 诊断瞬间的进程树；长生命周期的 CLI 会话结束后 CLI 显示「未运行」 |
| D7 | 服务器探测超时预算有限 | 服务器只读探测三项串行 + 单命令超时，服务器极慢时会部分项显示失败而非等待 |
| D8 | Desktop 多子进程无法逐一归属 | Desktop 常驻多个后台子进程；仅以「进程存在 + 证据强度」给出 verified/partial/unverified，不把任一子进程的连接推断为全部流量 |

## 三、安全边界（设计保证，见 docs/security.md）

- 私钥只存路径；日志/诊断/截图不含私钥内容、Token、请求正文。
- 全部外部进程参数数组启动；无 shell 拼接；命令白名单。
- 写配置：备份 → 原子写 → 读取回验；known_hosts 写前备份。
- 回滚只恢复本工具备份；检测到用户同时修改 → 拒绝覆盖并提示人工选择。
- 服务器现有业务（Docker、Nginx、CPA、SSH）零改动：应用只在服务器上建立普通 SSH 动态转发会话。
